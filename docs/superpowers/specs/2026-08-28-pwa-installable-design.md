# PWA / Installable — Design

Status: approved, sub-project 4 of 5
Date: 2026-08-28
Depends on: [Foundation rebuild](./2026-08-28-foundation-rebuild-design.md)

## Goal

Make the app installable ("add to home screen") and usable offline, so it
feels like an app you open daily rather than a bookmarked webpage. This is
also a hard prerequisite for push notifications (sub-project 5) to work at
all on iPhone — iOS only allows web push for a site installed to the home
screen.

## Manifest

Standard `manifest.json`, generated by `vite-plugin-pwa` from Vite config
rather than hand-written:

- `name` / `short_name` — the app's existing title ("Routine Chăm Sóc Bản
  Thân").
- `display: "standalone"` — no browser chrome once installed.
- `theme_color` / `background_color` — drawn from the existing `--rose` /
  `--cream` CSS variables, so the OS splash screen and status bar match the
  app's look.
- `start_url` — the app root. Combined with sub-project 2's "open on
  today's actual weekday" default, launching from the home screen icon
  lands you directly on today's routine.
- Icons — generated in the required sizes (192, 512, and a maskable
  variant) from the app's existing flower/petal motif (the `❀` glyph and
  petal SVG already used in section titles and hero headers) in the rose
  palette. No new visual identity being invented here — reusing what's
  already on the page.

## Service worker

Uses `vite-plugin-pwa`'s generated service worker (via Workbox under the
hood) rather than a hand-written one — this is a well-trodden,
purpose-built solution for exactly "Vite app + installable + offline app
shell," and keeps the amount of new hand-maintained caching logic at zero.

- **What's cached**: the built JS/CSS/HTML app shell (precache on install),
  so the app loads instantly and works offline for viewing/using the UI.
- **What's NOT cached/intercepted by the service worker**: calls to the
  Cloudflare Worker API (`GET`/`PUT /state`). Those already have their own
  offline fallback via `localStorage`, designed in the foundation
  sub-project — the service worker doesn't need to duplicate that.

## Updates

`vite-plugin-pwa`'s `registerType: "prompt"` mode (rather than
auto-update-and-reload) is used: when a new version is deployed and the
service worker detects a waiting update, the app shows a small,
non-blocking banner — "Update available — tap to refresh" — instead of
forcing a reload. This matters because sub-project 3 (the editor) has
in-progress form state that a silent forced reload could disrupt; the user
decides when it's a good time to refresh.

## Testing

- Lighthouse's PWA audit (installability, manifest validity, service
  worker registration) as an automated sanity check.
- Manual "add to home screen" verification on both Android (Chrome) and
  iOS (Safari) — iOS has real quirks (e.g. it only recognizes certain
  manifest fields, and push only works post-install) worth checking by
  hand rather than trusting Lighthouse alone.
- Manual offline check: disable network, reload the installed app, confirm
  the shell still renders and shows the last-cached `AppState`
  (`localStorage` fallback from the foundation).

## Out of scope

- Push notification subscription/sending → sub-project 5.
- Any offline *write* queueing beyond what the foundation already does
  (last-write-wins on next successful `PUT`) — not revisited here.
